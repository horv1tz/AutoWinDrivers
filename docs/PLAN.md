# AutoWinDrivers — план разработки

> Утилита для Windows 10/11, которая сканирует всё оборудование, находит под него драйверы,
> помогает их установить и в фоне следит за подключением новых устройств.
> Ядро и вся логика — на Rust. Интерфейс — уровня «флагманское приложение под Windows 11».

---

## 0. Коротко

| Что | Решение |
|---|---|
| Язык | Rust (stable, edition 2024), Cargo workspace |
| Windows API | крейт `windows` (windows-rs): SetupAPI / CfgMgr32 / WUA COM / WinTrust / WinRT |
| UI | **Tauri 2 + Svelte 5 + Tailwind**, стиль Fluent 2 / Windows 11 (Mica, системный акцент, тёмная/светлая тема). Альтернатива на 100 % Rust — Dioxus (см. открытые вопросы) |
| Источники драйверов v1 | Windows Update Agent (официальный COM API) → Microsoft Update Catalog → локальный DriverStore / папки с INF |
| Источники v2 | вендоры (NVIDIA, AMD, Intel, Realtek), офлайн‑драйверпаки |
| Установка | WUA Installer / `pnputil` / `DiInstallDriver` / `UpdateDriverForPlugAndPlayDevices`, только подписанные драйверы, точка восстановления + бэкап перед установкой |
| Мониторинг | `CM_Register_Notification` (CfgMgr32), трей‑агент, тосты Windows, автозапуск через Планировщик |
| Срок MVP | ~17 недель для одного разработчика; при двух (backend + UI) — ~11–12 недель |

## 1. Цели и требования

### 1.1 Функциональные

1. **Сканирование оборудования.** Полный список устройств (включая скрытые/отключённые/отсутствующие по желанию) с группировкой по классам, статусом, кодом проблемы, Hardware ID / Compatible ID, установленным драйвером (версия, дата, поставщик, INF, подпись).
2. **Поиск драйверов.** Для каждого устройства — список кандидатов из нескольких источников, с ранжированием «как у Windows» и понятным объяснением, почему именно этот драйвер рекомендован.
3. **Помощь в установке.** Пошаговый мастер: выбор → проверка подписи → точка восстановления и бэкап → загрузка → установка → перезагрузка при необходимости → откат, если что-то пошло не так.
4. **Отслеживание новых устройств.** Фоновый агент в трее: подключили устройство → если нет драйвера или он с проблемой → ищем → показываем уведомление «драйвер найден, установить?» (или ставим автоматически по политике пользователя).
5. **Бэкап и восстановление.** Экспорт всех установленных драйверов, восстановление, история установок с откатом.
6. **CLI.** Все операции доступны из командной строки (`awd scan --json`, `awd search`, `awd install`) — для отладки, скриптов и продвинутых пользователей.

### 1.2 Нефункциональные

- Windows 10 22H2 и Windows 11 (23H2/24H2+), x64 обязательно, ARM64 — цель v1.1.
- Запуск без прав администратора; повышение прав только для операций, которым оно реально нужно.
- Безопасность по умолчанию: никаких неподписанных драйверов, никаких отключений проверки подписи, только HTTPS, проверка хешей загрузок.
- Отзывчивый UI: сканирование и поиск не блокируют интерфейс, прогресс по каждой операции.
- Локализация: RU + EN с первого релиза.
- Телеметрия — только opt‑in (крэш‑репорты), по умолчанию выключена.
- Один установщик (MSI/NSIS) + портативная версия, автообновление с проверкой подписи.

### 1.3 Вне скоупа v1

- Linux/macOS.
- Свой хостинг драйверов (только официальные источники, ничего не раздаём сами).
- Установка драйверов в офлайн‑образ (DISM) — кандидат на v2.
- BIOS/UEFI‑прошивки.

## 2. Ключевые технические решения

### 2.1 Почему Tauri 2 для UI

Задача — «просто ахуенный интерфейс». Реально премиальный вид на Windows сегодня даёт веб‑стек поверх WebView2 (он уже встроен в Windows 10/11): анимации, микровзаимодействия, компоненты, типографика. Tauri 2 даёт это с Rust‑бэкендом, бинарником ~10 МБ, нативным треем, уведомлениями, автообновлением и Mica/Acrylic через `window-vibrancy`.

Вся бизнес‑логика, работа с Windows API, сеть, установка — в Rust‑крейтах, которые не знают про UI. Фронтенд — тонкий слой отображения.

Если принципиально нужно 100 % Rust без TypeScript — **Dioxus 0.6+** (тот же WebView2, разметка RSX на Rust, Tailwind). Цена: меньше готовых компонентов и анимаций, больше ручной работы ради того же вида. Решение надо принять до начала этапа 4 (см. §11).

### 2.2 Работа с устройствами

- Перечисление: `SetupDiGetClassDevsW` + `SetupDiEnumDeviceInfo` / `CM_Get_Device_ID_ListW`.
- Свойства через унифицированный Property API: `SetupDiGetDevicePropertyW` / `CM_Get_DevNode_PropertyW` с `DEVPKEY_*`:
  `Device_HardwareIds`, `Device_CompatibleIds`, `Device_InstanceId`, `Device_Class`, `Device_ClassGuid`, `Device_FriendlyName`, `Device_DeviceDesc`, `Device_Manufacturer`, `Device_LocationInfo`, `Device_BusReportedDeviceDesc`, `Device_DriverVersion`, `Device_DriverDate`, `Device_DriverProvider`, `Device_DriverInfPath`, `Device_DriverInfSection`, `Device_ProblemCode`, `Device_IsPresent`, `Device_Parent`, `Device_Children`.
- Статус: `CM_Get_DevNode_Status` → расшифровка `CM_PROB_*` (28 — нет драйвера, 1 — не настроено, 10 — не запускается, 43 — остановлено Windows, 52 — проблема с подписью и т.д.) в человеческие тексты и рекомендации.
- Подпись установленного драйвера: `WinVerifyTrust` по `.cat` из DriverStore.
- Сводка о системе (для дашборда): CPU/RAM/материнская плата/ОС через WMI (`wmi` крейт) и `GetSystemFirmwareTable('RSMB')`, GPU через DXGI.

### 2.3 Источники драйверов (провайдеры)

Общий трейт:

```rust
#[async_trait]
pub trait DriverProvider: Send + Sync {
    fn id(&self) -> ProviderId;
    async fn search(&self, dev: &Device, ctx: &SearchCtx) -> Result<Vec<DriverCandidate>>;
    async fn fetch(&self, cand: &DriverCandidate, sink: ProgressSink) -> Result<DriverPackage>;
}
```

| Провайдер | Как | Статус API | Этап |
|---|---|---|---|
| **WindowsUpdate** | WUA COM: `IUpdateSession` → `IUpdateSearcher` с `ServiceID = 7971f918-a847-4430-9279-4a52d1efe18d` (Microsoft Update), критерий `IsInstalled=0 and Type='Driver'`. Результаты — `IWindowsDriverUpdate` (HWID, производитель, дата, модель). Загрузка/установка — `IUpdateDownloader` / `IUpdateInstaller` | официальный | 2 |
| **MicrosoftCatalog** | `catalog.update.microsoft.com/Search.aspx?q=<HWID>` → HTML‑таблица → `DownloadDialog.aspx` → ссылки на `.cab`. Распаковка `.cab` (крейт `cab`), парсинг INF | неофициальный, хрупкий; только как дополнение к WUA, с кэшем и лимитами | 2 |
| **LocalStore** | DriverStore (`pnputil /enum-drivers` или обход `FileRepository`), папки пользователя, смонтированные образы — индексация INF и подбор по HWID. Позволяет находить «более новый драйвер уже лежит в системе, но не применён» | локально | 2 |
| **DriverPacks** | офлайн‑паки формата SDI (`DP_*.7z` + индекс INF) для машин без интернета | локально | 7 |
| **Vendor: NVIDIA / AMD / Intel / Realtek** | по одному модулю на вендора (у NVIDIA есть JSON‑эндпоинт подбора драйверов; остальные — исследование). Для `.exe`‑инсталляторов — запуск с известными тихими флагами либо ведём пользователя за руку | полуофициальные | 7 |

### 2.4 Алгоритм подбора и ранжирования

Повторяем логику Windows, чтобы наши рекомендации совпадали с тем, что сделал бы сам PnP‑менеджер, но объясняем их пользователю:

1. Берём список HWID устройства (от самого специфичного к общему), затем Compatible ID.
2. Для каждого кандидата (INF‑модель или запись WU) считаем ранг по схеме `0xSSGGTHHH`: подпись (WHQL/inbox < Authenticode < не подписан — последние отбрасываем), feature score, тип совпадения (HWID↔HWID лучше, чем через Compatible ID), индекс HWID в списке устройства.
3. При равном ранге — новее дата, затем выше версия (сравнение версий `a.b.c.d` числовое, не строковое).
4. Фильтруем по ОС и архитектуре: декорированные секции INF `NTamd64.10.0...19041`, `NTarm64`, диапазоны версий сборки.
5. Выдаём: «Рекомендуем», «Альтернативы», «Не подходит (почему)».

Отдельный модуль — **парсер INF** (своего крейта в экосистеме нет): секции `[Version]`, `[Manufacturer]`, `[Models.*]`, подстановка `%strings%`, `DriverVer`, `CatalogFile`, декорации по ОС/архитектуре. Покрываем тестами на реальных INF из DriverStore и фаззингом.

### 2.5 Установка

Пайплайн — конечный автомат с событиями прогресса (чтобы UI и CLI показывали одно и то же):

```
Selected → PreflightChecks → RestorePoint → Backup → Download → VerifySignature
        → Install → PostCheck(status устройства) → Done | RebootRequired | Failed → Rollback?
```

- **Preflight:** место на диске, питание (ноутбук от батареи — предупреждаем), Windows Update не занят, нет pending reboot.
- **Точка восстановления:** WMI `root\default:SystemRestore.CreateRestorePoint(..., RestorePointType=10 DEVICE_DRIVER_INSTALL)`. Учитываем лимит «одна точка в 24 ч» (`SystemRestorePointCreationFrequency`) — не падаем, а предупреждаем.
- **Бэкап:** `pnputil /export-driver <oem.inf> <dir>` текущего драйвера устройства + запись в историю.
- **Загрузка:** `reqwest` с докачкой, SHA‑256 сверяем с тем, что отдал источник.
- **Подпись:** `WinVerifyTrust` (`WINTRUST_ACTION_GENERIC_VERIFY_V2`) по `.cat`; без валидной подписи установка невозможна — только сообщение.
- **Установка:**
  - из WUA — `IUpdateInstaller` (сам ставит, сам говорит про перезагрузку);
  - из INF — `DiInstallDriverW` (newdev.dll) для добавления в DriverStore + `UpdateDriverForPlugAndPlayDevicesW` для адресной установки на конкретный HWID; `pnputil /add-driver /install` как запасной путь;
  - `.exe` вендора — запуск с тихими ключами, иначе интерактивно с подсказками.
- **Откат:** `DiRollbackDriver`, либо восстановление из бэкапа.
- **Права:** UI работает без админа. Привилегированные операции выполняет отдельный процесс‑воркер `awd-worker`, который запускается через UAC один раз на сессию и общается с UI по именованному каналу (JSON‑RPC, `awd-ipc`). Так UAC‑окно показывается один раз, а не на каждое действие, и трей‑агент не висит под админом постоянно. На этапе 3 допускается упрощение (манифест `requireAdministrator`), разделение — до релиза.

### 2.6 Мониторинг новых устройств

- `CM_Register_Notification` с фильтром `CM_NOTIFY_FILTER_TYPE_DEVICEINSTANCE` + `CM_NOTIFY_FILTER_FLAG_ALL_DEVICE_INSTANCES` — колбэки `DEVICEINSTANCEENUMERATED / STARTED / REMOVED` без окна и message loop. Запас — `RegisterDeviceNotificationW` (`WM_DEVICECHANGE`) и WMI `Win32_DeviceChangeEvent`.
- Дебаунс 3–5 с (Windows сама пытается поставить драйвер через WU), затем перечитываем узел: если `CM_PROB_FAILED_INSTALL` / `NOT_CONFIGURED` / `FAILED_START` — запускаем поиск.
- Уведомление — WinRT `ToastNotification` с кнопками «Установить» / «Подробнее» / «Игнорировать это устройство» (через `tauri-plugin-notification`; регистрацию AUMID для непакетированного приложения проверить отдельно на этапе 5).
- Политики: «Спрашивать» (по умолчанию) / «Ставить автоматически только WHQL из Windows Update» / «Только уведомлять».
- Автозапуск — задача Планировщика при входе пользователя (без UAC‑окна при старте), опционально ключ `Run`.
- Журнал событий: что подключили, что нашли, что сделали.

### 2.7 Хранение, логи, конфиг

- SQLite (`rusqlite`, bundled) в `%LOCALAPPDATA%\AutoWinDrivers\`: история сканов, кэш поисков (TTL), история установок/бэкапов, журнал агента.
- Настройки — `settings.toml` (serde), миграции версий.
- Логи — `tracing` + `tracing-appender` (ротация), кнопка «Собрать диагностику» (zip логов + JSON‑дамп устройств без персональных данных).

### 3.1 Крейты

| Крейт | Назначение | Собирается на Linux (CI) |
|---|---|---|
| `awd-core` | доменная модель, INF‑парсер, матчинг, версии, пайплайн установки как state machine, трейты `DeviceSource`/`DriverProvider`/`Installer` | да |
| `awd-win` | реализация трейтов через Windows API; весь `unsafe` здесь; `#[cfg(windows)]` | нет (есть mock‑реализации для тестов) |
| `awd-providers` | провайдеры драйверов, HTTP‑клиент, кэш, парсинг Catalog | да (сетевые части за фичами) |
| `awd-ipc` | протокол UI ↔ воркер ↔ агент, сериализация, named pipes | частично |
| `awd-worker` | привилегированный процесс | нет |
| `awd-agent` | трей‑агент/мониторинг | нет |
| `awd-cli` | CLI (`clap`), JSON‑вывод | нет |
| `apps/desktop` | Tauri‑приложение | нет |

### 3.2 Модель данных (ядро)

```rust
pub struct Device {
    pub instance_id: String,          // PCI\VEN_8086&DEV_...\3&11583659&0&FE
    pub name: String,                 // FriendlyName или DeviceDesc
    pub class: DeviceClass,           // + class_guid
    pub manufacturer: Option<String>,
    pub hardware_ids: Vec<HardwareId>,
    pub compatible_ids: Vec<HardwareId>,
    pub location: Option<String>,
    pub present: bool,
    pub status: DeviceStatus,         // Ok | Problem(CmProblem) | Disabled | Hidden
    pub driver: Option<InstalledDriver>, // provider, version, date, inf, signed, is_inbox
}

pub struct DriverCandidate {
    pub source: ProviderId,
    pub title: String,
    pub provider_name: String,        // поставщик драйвера
    pub version: DriverVersion,       // сравнимая
    pub date: NaiveDate,
    pub matched_by: MatchKind,        // HardwareId(idx) | CompatibleId(idx)
    pub rank: u32,                    // как у Windows, меньше — лучше
    pub signature: SignatureKind,     // Whql | Authenticode | Unsigned
    pub size: Option<u64>,
    pub download: DownloadRef,
    pub verdict: Verdict,             // Recommended | Alternative | NotApplicable(reason)
}
```

## 4. UI / UX

### 4.1 Дизайн‑система

- **Fluent 2 / Windows 11:** фон Mica (Win11) или акрил/сплошной (Win10), боковая навигация, скругления 8 px, Segoe UI Variable, системный акцентный цвет (`UISettings::GetColorValue`), автоматическая тёмная/светлая тема, плавные переходы между экранами, skeleton‑загрузчики, пустые состояния с иллюстрациями.
- Иконки: Fluent UI System Icons; иконки классов устройств — свои, в едином стиле.
- Доступность: полная клавиатурная навигация, фокус‑кольца, контраст, уважение `prefers-reduced-motion`.
- Макеты сначала в Figma/Penpot (этап 0), затем компоненты.

### 4.2 Экраны

1. **Обзор.** «Здоровье системы» (кольцо/счёт), счётчики: OK / без драйвера / устарели / с ошибкой; большая кнопка «Сканировать»; карточка ПК (CPU, GPU, RAM, плата, Windows); лента последних событий агента.
2. **Устройства.** Дерево по классам или плоский список; фильтры «только проблемы», «устаревшие», «скрытые»; поиск по имени/HWID; панель устройства справа: статус с объяснением, HWID с копированием, текущий драйвер, кандидаты, действия (обновить, откатить, отключить, удалить, открыть в Диспетчере устройств).
3. **Драйверы.** Все рекомендации одним списком с чекбоксами, бейджи источника, «было → станет», размер, подпись; «Установить выбранные».
4. **Мастер установки.** Шаги пайплайна с прогрессом, лог в раскрывающемся блоке, итог, кнопка «Перезагрузить сейчас / позже».
5. **Мониторинг.** Состояние агента, политика, журнал подключений/действий, игнор‑лист устройств.
6. **Бэкапы.** Экспорт всех драйверов, восстановление, история установок с откатом в один клик.
7. **Настройки.** Источники, политика автоустановки, автозапуск, тема, язык, прокси, диагностика, о программе/проверить обновления.
8. **Трей.** Иконка со статусом, меню: сканировать, пауза мониторинга, открыть, выход. Тосты на новые устройства.

| 7 | **После MVP** | — | Вендорские провайдеры, офлайн‑драйверпаки, ARM64, DISM для офлайн‑образов, плагины провайдеров, доп. языки |

Критерии готовности MVP: на чистой Win10 22H2 и Win11 24H2 (x64, физическая машина + Hyper‑V) приложение находит и ставит драйверы для устройств с кодом 28 через WU/Catalog, агент ловит подключение USB‑устройства и предлагает драйвер, установка откатывается из бэкапа, UI проходит дизайн‑ревью.

## 6. Тестирование и CI/CD

- **Юнит‑тесты (Linux + Windows):** INF‑парсер (корпус реальных INF), ранжирование, сравнение версий, разбор Catalog‑HTML (сохранённые фикстуры), state machine пайплайна с mock‑установщиком.
- **Фаззинг:** `cargo-fuzz` для INF‑парсера и парсера Catalog.
- **Интеграционные (GitHub Actions `windows-latest`):** перечисление устройств на раннере, чтение DriverStore, WUA‑поиск как smoke‑тест (допускаем сетевые флаки — помечаем отдельно).
- **UI:** `tauri-driver` + WebDriver для сценариев, визуальные снапшоты ключевых экранов в обеих темах.
- **Ручная матрица:** Win10 22H2, Win11 23H2/24H2; x64 (+ ARM64 позже); ноутбук + десктоп + ВМ; устройства: USB‑флешка, веб‑камера, Bluetooth‑адаптер, Wi‑Fi, GPU, принтер; сценарии «нет интернета», «WU отключён политикой», «ноутбук от батареи».
- **CI:** `cargo fmt --check`, `clippy -D warnings`, `cargo deny` (лицензии/уязвимости), `cargo test`, сборка Tauri‑бандла на каждый PR, релиз по тегу с подписью.
- **Подпись кода:** Azure Trusted Signing или OV/EV‑сертификат — без подписи SmartScreen будет пугать пользователей, а WebView2/установщик драйверов — повод для ложных срабатываний антивирусов.

## 7. Риски и как их гасим

| Риск | Мера |
|---|---|
| У Microsoft Update Catalog нет официального API — парсинг может сломаться, возможны лимиты | WUA как основной источник; Catalog — дополнение; фикстуры в тестах; кэш; мягкая деградация с понятным сообщением |
| Плохой драйвер ломает систему (особенно GPU/чипсет) | точка восстановления + бэкап перед каждой установкой, только WHQL по умолчанию, никакой автоустановки без явного согласия, блок‑лист известных проблемных версий |
| Вендорские сайты меняются, `.exe`‑инсталляторы не всегда ставятся тихо | вендоры — отдельные модули после MVP, деградация до «скачать и запустить с подсказками» |
| `unsafe`/COM/FFI — утечки и падения | весь `unsafe` в `awd-win`, безопасные обёртки, RAII для хэндлов и COM, Miri/ASan где возможно |
| UAC и права | один воркер с одним UAC‑окном на сессию; агент без прав; Планировщик для автозапуска |
| Windows 10 — потребительский ESU закончился в октябре 2026 | поддерживаем 22H2 как просил заказчик, но тестируем в первую очередь Win11; WebView2 Evergreen‑бутстраппер в установщике |
| ARM64 | архитектуру учитываем в модели с первого дня (фильтр секций INF), сборку — в v1.1 |
| Юридическое: раздача чужих драйверов | ничего не хостим, качаем только из официальных источников, показываем EULA вендора |
| SmartScreen/антивирусы | подпись кода, репутация через winget, без упаковщиков/обфускации |
