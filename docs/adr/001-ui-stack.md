# ADR-001. Стек интерфейса: Tauri 2 + Svelte 5

**Статус:** принято, 2026-10-24.

## Контекст

Нужен интерфейс уровня флагманского приложения Windows 11 при минимальном потреблении ресурсов.
Вся бизнес-логика в любом случае пишется на Rust. Рассматривались:

| Вариант | Внешний вид | Производительность | Экосистема |
|---|---|---|---|
| Tauri 2 + Svelte 5 | веб-уровень: анимации, типографика, Fluent-компоненты | WebView2 общий с системой, Svelte без virtual DOM (~2–5 КБ рантайма), тяжёлая работа в Rust | очень большая |
| Dioxus 0.6 (desktop) | тот же WebView2, разметка RSX на Rust | та же, что у Tauri | мало готовых компонентов и анимаций |
| Slint / iced / egui | нативный рендер, но «не как Windows 11» | лучше по RAM/старту | не хватает компонентов для премиального вида |

## Решение

**Tauri 2 + Svelte 5 + Tailwind.**
Рендер один и тот же, что у Dioxus (WebView2), но зрелая экосистема компонентов и анимаций
даёт лучший внешний вид за меньшее время. Фронтенд остаётся тонким слоем отображения,
никакой логики подбора/установки в нём нет. Нативные Rust-UI отклонены из-за внешнего вида.

Целевые метрики, по которым решение будет перепроверено после этапа 4:

- холодный старт до интерактивного окна — не более 1 с на SSD;
- потребление памяти в покое (окно открыто, скан не идёт) — не более 150 МБ суммарно по процессам;
- список из 500 устройств скроллится без просадок (виртуализация списка обязательна);
- агент в трее без UI — не более 30 МБ.

## Последствия

- Фронтенд на TypeScript; строгая граница: UI вызывает команды Tauri, которые делегируют в `awd-core`.
- Нужен Node.js в CI и у разработчиков фронтенда.
- Mica/Acrylic через `window-vibrancy`, системный акцент через WinRT `UISettings`.
- Если метрики не достигаются, запасной вариант — Dioxus с тем же Rust-бэкендом; крейты от этого не зависят.
